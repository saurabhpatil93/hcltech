# Data card

## Summary

Fictional Northstar Market support dataset for local development, demos, and evaluation only. It contains synthetic customers, products, orders, order items, returns, and fictional policy documents. No real customer records are intentionally used.

## Provenance and generation

- The checked-in operational CSV output is generated by `scripts/generate_synthetic_data.py` with Python's `random` module and seed `20261010`.
- This generator does not call an LLM. It prints the separate prompt artifact in `data/synthetic_data_prompt.txt` for teams that need to create and preserve a separately disclosed LLM-generated dataset.
- Dataset generation uses a fixed evaluation date of 2026-10-01 for selected boundary cases.
- The source and rule metadata are documented in `data/source_register.csv` and `data/rule_registry.csv`. `scripts/init_demo.py` writes the policy documents, indexes them, and loads the cited rules into SQLite.

## Composition

| File | Rows in bundled output | Contents |
|---|---:|---|
| `data/csv/customers.csv` | 35 | Fictional customer IDs, names, tiers, cities, and joined years |
| `data/csv/products.csv` | 22 | Fictional products, categories, prices, and warranty months |
| `data/csv/orders.csv` | 70 | Orders across multiple statuses and payment methods |
| `data/csv/order_items.csv` | 70 | One item row per seeded order, including selected discounts and delivery dates |
| `data/csv/returns.csv` | 1 | A seeded return request |

The validator checks file schemas, minimum row counts, identifiers, selected constraints, and references between customer/order/product/return rows. Run `python scripts/validate_data.py --dir data/csv` before loading.

## Intended use

Testing and demonstrating policy retrieval, source citations, customer-scoped order lookup, deterministic return/refund/warranty calculations, and adversarial instruction-like user data.

## Limitations and risks

- Names, cities, amounts, and policies are fabricated examples and are not statistically representative of any population or retailer.
- A generated name or other value could coincidentally resemble real-world data; do not treat that as evidence the data is real or use this dataset to identify people.
- Edge cases are hand-authored and do not cover every date, currency, policy conflict, or transaction state.
- Delivery notes intentionally include instruction-like text in a small number of records so the application can demonstrate that user-controlled text is untrusted.
- The data must not be used for real customer service, production decisions, model training claims, or financial calculations.
- If evaluation rules require LLM-generated data, use an approved model, retain the exact model/version, prompt, raw output, and validation results, and clearly distinguish those outputs from this seeded-Python dataset.
